# Labornetzteil 600 V / 3 kW – digital controller firmware

STM32G474RETx, hard-switched (non phase-shifted) full bridge, voltage mode, 100 kHz.
Output voltage and current are measured by two external **MCP33131-10** (16 bit, 1 Msps)
SAR ADCs. Sampling, conversion wait, SPI read-out and the hand-over to the control loop
are sequenced entirely in hardware (HRTIM → DMA → SPI → DMA). The CPU runs once per
switching period in a single interrupt.

All peripheral configuration lives in **`Labornetzteil_600V_3kW_Digitaler_Regler.ioc`**
and is generated by CubeMX. The application code only adds what CubeMX cannot express.

## 1. Hardware chain

```
HRTIM Timer E  CMP1 ─► TE1 + TE2 rise ─► both ADCs sample (CNVST)
               CMP2 ─► TE1 falls (ADC_V drives SDO) + DMA request HRTIM1_E
                         DMA1 Ch1: pwr_spi_dummy ─► SPI1->DR ─► 16 SCLK ─► SPI1_RX
               CMP3 ─► TE2 falls (ADC_I drives SDO) + DMA request HRTIM1_E
                         DMA1 Ch1: pwr_spi_dummy ─► SPI1->DR ─► 16 SCLK ─► SPI1_RX
SPI1_RX ─► DMA1 Ch2 (circular, 2 half-words) ─► transfer complete IRQ
         ─► DMA1_Channel2_IRQHandler (pwr_ctrl.c): CV + CC 3p3z, lower duty wins
         ─► HRTIM Timer A CMP1/CMP3 (preload, update at the next period start)

Hardware over-current trip (no CPU, no software latency):
PC1 (I_SENSE) ─► COMP3 (+)
DAC3 OUT1     ─► COMP3 (−)          threshold = PWR_OCP_HW_A / pwr_set_ocp_hw()
COMP3 out     ─► HRTIM FLT5 ─► TA1 + TA2 forced low (fault state), latched
                 control ISR ─► PWR_FAULT_OCP_HW, bridge stays off until cleared
```

The two MCP33131 share SCLK **and SDO**: an MCP33131 releases SDO (Hi-Z) after its
16th bit, so the ADC whose CNVST falls second can use the same line. They cannot be
daisy-chained (SDI must be tied high).

## 2. Pinout

| Pin  | Function     | Label        | Connection                                   |
|------|--------------|--------------|----------------------------------------------|
| PA8  | HRTIM1_CHA1  | `DIAG1_Q1_Q4`| diagonal 1: gate drivers of Q1 (leg A high) and Q4 (leg B low) |
| PA9  | HRTIM1_CHA2  | `DIAG2_Q2_Q3`| diagonal 2: gate drivers of Q2 (leg A low) and Q3 (leg B high) |
| PC8  | HRTIM1_CHE1  | `ADC_V_CNVST`| CNVST of the voltage ADC                     |
| PC9  | HRTIM1_CHE2  | `ADC_I_CNVST`| CNVST of the current ADC                     |
| PA5  | SPI1_SCK     | `ADC_SCLK`   | SCLK of both ADCs                            |
| PA6  | SPI1_MISO    | `ADC_SDO`    | SDO of both ADCs (wired together), pull-up   |
| PA7  | SPI1_MOSI    | `SPI1_MOSI_NC` | not connected (CubeMX full-duplex mode needs it) |
| PC1  | COMP3_INP    | `I_SENSE`    | current sense signal for the hardware OCP (0 … 3.3 V) |
| PB1  | GPIO output  | `DBG_ISR`    | high while the control ISR runs (scope)      |
| PA13/PA14 | SWD     |              | debugger                                     |

* Each HRTIM output drives the two gate drivers of one diagonal. Both transistors of a
  leg are never on together: diagonal 1 conducts only in the first half period,
  diagonal 2 only in the second, and the duty limit (`PWR_DUTY_MAX_PERMILLE` = 950)
  leaves T/2 × (1 − d_max) = 250 ns between them. No HRTIM dead-time unit is used:
  gate-driver delay mismatch plus switch turn-off time must fit into these 250 ns.
  `pwr_init()` refuses a gap below `PWR_DIAG_GAP_MIN_NS` (config check 48).
  `pwr_init()` checks the TA1/TA2 set/reset sources, polarity and dead-time bit
  (config checks 36/37) and keeps the bridge disabled if they differ.
* Tie SDI and DVIO of both ADCs to 3.3 V.
* 33 Ω series resistors at SDO and SCLK of each ADC; keep the shared SDO stub short.
* Pull-downs (~100 kΩ) on both diagonal outputs and both CNVST lines: the pins are
  unconfigured until `MX_HRTIM1_Init()` runs.
* SYS → *Disable dead battery signals* is enabled: PA9 is a UCPD dead-battery pin
  and would otherwise keep its internal pull-down.
* PC1 goes straight into the comparator: keep it within 0 … VDDA and add a small RC
  close to the pin (time constant well below the time the switches survive the
  over-current) if switching noise reaches it. Every crossing of the threshold
  trips, there is no blanking window.

`pwr_init()` reads the timing back from the HRTIM registers and checks it against the
limits in `pwr_config.h`. If something does not fit, `pwr_status()->fault` gets
`PWR_FAULT_CONFIG`, `config_check` holds the number of the failed check (see
`check_ocp_config()` 50–61, `check_dma_config()` 1–21, `check_timing_config()` 30–48),
and the bridge cannot be enabled.

### Changing the timing in CubeMX

All values are HRTIM ticks of 1/(170 MHz × 32) = 183.8 ps.

* **Switching frequency**: Period of Timer A and E = 5.44 GHz / f_sw. Then set
  CMP2 of Timer A to Period/2 (checked) and move the Timer E compares.
* **Sampling instant** (Timer E CMP1) is the low-duty position, in the off-time after
  diagonal 1 turns off. It must lie at least `PWR_SAMPLE_SETTLE_NS` after the turn-off
  edge at the switch-over duty: CMP1 ≥ Period/2 × `PWR_SAMPLE_HI_ENTER_PERMILLE`/1000
  + settle (check 41). If `PWR_DUTY_MAX_PERMILLE` stays below CMP1 − settle, the
  position never switches.
* **CMP2** ≥ CMP1 + `PWR_ADC_TCNV_NS` (conversion time).
* **CMP3** ≥ CMP2 + 16 SCLK periods + `PWR_ADC_DMA_MARGIN_NS`.
* CMP3 + frame + `PWR_COMPUTE_BUDGET_NS` ≤ Period (time for the ISR).
* The high-duty position is derived by the firmware: the same three compares,
  shifted so that CMP1 = Period/2 + `PWR_SAMPLE_ON_SETTLE_NS`. Its conversion must end
  before diagonal 2 turns off at the switch-back duty (check 46), and its CMP3 must
  still leave the ISR budget (check 47).

## 4. Timing (defaults)

The bridge runs from d = 0 to 0.95. Each half period has two edge-free stretches,
the on-time (d × 5 µs) and the off-time ((1 − d) × 5 µs); the ADCs need ~1.1 µs of
quiet (settling + conversion). At low duty only the off-time is long enough, at high
duty only the on-time. So the sampling instant moves with the duty, never the PWM:

| | Low duty (off-time position) | High duty (on-time position) |
|---|---|---|
| Used for | d < 0.55, back below 0.45 | d > 0.55, until it falls below 0.45 |
| Valid range | d ≤ 0.76 | d ≥ 0.26 |
| Both CNVST rise (sample) | **4.10 µs** (CMP1 22304) | **5.50 µs** (CMP1 29920) |
| Conversion done | 4.85 µs | 6.25 µs |
| CNVST_V falls, frame 1 | 4.90 µs (CMP2 26656) | 6.30 µs (CMP2 34272) |
| CNVST_I falls, frame 2 | 5.53 µs (CMP3 30067) | 6.93 µs (CMP3 37683) |
| Both words in RAM → control ISR | ~5.95 µs | ~7.35 µs |

Edges of the bridge: TA1 on at 0, off at d × 5 µs (≤ 4.75 µs); TA2 on at 5.00 µs, off
at 5.00 + d × 5 µs (≤ 9.75 µs). The new duty and the matching sampling position are
written in the same update-disable block and take effect together at the next period
start (10.0 µs). `pwr_status()` shows the position of the last sample (`sample_hi`)
and the number of switches (`sample_switches`); a steadily rising count would mean
the duty oscillates across the whole hysteresis band.

## 5. Code structure

| File | Content | Regenerated by CubeMX? |
|---|---|---|
| `Core/Src/main.c`, `stm32g4xx_hal_msp.c`, `stm32g4xx_it.c`, `Core/Inc/main.h`, … | CubeMX output | yes; user code only inside `USER CODE` blocks |
| `Core/Inc/pwr_config.h` | control parameters, scaling, limits, compensator coefficients | no |
| `Core/Inc/pwr_ctrl.h`, `Core/Src/pwr_ctrl.c` | config check, hardware OCP arming, ADC recalibration, DMA start, control ISR, protection | no |
| `Core/Inc/comp3p3z.h` | 3p3z compensator (split into a fast and a deferred half) | no |

User-code hooks in generated files:

* `main.c` → Includes: `#include "pwr_ctrl.h"` (declares `pwr_spi_dummy`, used by the
  generated `MX_HRTIM1_Init()`).
* `main.c` → USER CODE 2: `pwr_init(&hhrtim1, &hspi1, &hcomp3, &hdac3);` and set-points.
  **The bridge is not enabled automatically**; call `pwr_output_on()` deliberately.
* `main.c` → `Error_Handler()`, `stm32g4xx_it.c` → `HardFault_Handler()`:
  `pwr_emergency_off()`.
* `stm32g4xx_it.c` → `SysTick_Handler()`: `pwr_tick_1ms()` (trips if the control ISR
  stops for `PWR_WATCHDOG_MS`).

`pwr_ctrl.c` compiles itself with `-O2` (`#pragma GCC optimize`), so the ISR is the
same in Debug and Release builds.

### 3p3z convention

```
u[n] = B0·e[n] + B1·e[n-1] + B2·e[n-2] + B3·e[n-3] + A1·u[n-1] + A2·u[n-2] + A3·u[n-3]

        B0 + B1 z⁻¹ + B2 z⁻² + B3 z⁻³
H(z) = -------------------------------      e in V (or A), u = duty, Ts = 1/f_sw
        1 − A1 z⁻¹ − A2 z⁻² − A3 z⁻³
```

From `c2d(Gc, Ts, 'tustin')` with `den = [1 a1 a2 a3]`: **A1 = −a1, A2 = −a2, A3 = −a3**,
B0…B3 = num. The defaults are slow pure integrators (placeholders).

CV and CC run in parallel; the lower duty wins. Both compensators are then fed the
duty that was actually applied (anti-windup for clamping and CV/CC hand-over).

### Hardware over-current trip

* Trip level at start-up: `PWR_OCP_HW_A`. At run time: `pwr_set_ocp_hw(amps)`, which
  returns the level actually applied (12-bit DAC, ~0.8 mV per step at PC1).
  `pwr_status()` shows `ocp_hw_a`, `ocp_hw_dac`, `ocp_hw_comp` (COMP3 output) and
  `ocp_hw_trips`.
* A trip forces TA1/TA2 low in hardware and is latched as `PWR_FAULT_OCP_HW`.
  `pwr_clear_fault()` releases it only when COMP3 is low again; then
  `pwr_output_on()` restarts with the soft-start ramp.
* The software OCP (`PWR_OCP_A`, ADC reading, once per period) stays active as a
  second, slower layer.
* `pwr_init()` locks the COMP3 configuration and the FLT5 settings until the next
  reset, and Timer A's fault enable is read-only (CubeMX: fault lock read-only).

## 7. Bring-up

1. **No power on the bridge.** Flash, run, watch `pwr_status()` in the debugger:
   * `fault == 0`, `config_check == 0`, `warn == 0`
     (`PWR_WARN_ADC_RECAL`: an ADC did not release SDO after recalibration).
   * `isr_count` rises by `f_sw_hz` per second, `isr_late_count == 0`,
     `isr_exit_ticks_max × t_tick_ps` below the period (at high duty the ISR starts
     ~1.4 µs later, so this is the number to watch there).
   * `raw_v` / `raw_i` match known test voltages at the ADC inputs.
2. Scope, triggered on PA8: PA9 is the same pulse shifted by 5 µs and never overlaps
   PA8; PC8/PC9 rise together at 4.1 µs, PC8 falls at 4.9 µs, PC9 at 5.53 µs; two
   bursts of 16 clocks on PA5; PB1 pulses once per period. Above d = 0.55 the CNVST
   pattern moves to 5.5 / 6.3 / 6.93 µs (`sample_hi` = 1), below 0.45 it returns.
   With the power stage running, check the ADC inputs right after the TA2 turn-on
   edge: the ringing must have settled within `PWR_SAMPLE_ON_SETTLE_NS` (500 ns).
3. Bad readings (powers of two, noisy LSBs): the falling-edge capture relies on the
   ADC's output hold time. In CubeMX set SPI1 *Clock Phase* = 1 Edge and prescaler 8
   (21.25 MHz), then set Timer E CMP3 ≥ 32112 (CMP2 + 753 ns frame + 250 ns margin).
4. Hardware OCP, still without bridge supply: set `PWR_OPEN_LOOP 1`, call
   `pwr_output_on()`, and raise the voltage at PC1 with a lab supply (stay below 3.3 V). TA1/TA2 must stop
   at `ocp_hw_a × PWR_OCP_HW_SENSE_V_PER_A + offset`, `fault` must show
   `PWR_FAULT_OCP_HW`, and `pwr_clear_fault()` must fail until PC1 is lowered again.
   Measure the delay from PC1 crossing to PA8/PA9 low on the scope.
5. Open loop (`PWR_OPEN_LOOP 1`, low duty) at reduced input voltage with a resistive load.
6. Closed loop with the default integrators, then with your 3p3z coefficients.

## 8. Safety notes

* Over-current is caught in hardware (COMP3 → FLT5, no CPU involved) and in software
  (ADC reading, once per period). OVP, DMA errors and the ISR watchdog are software
  only. A second comparator (e.g. on an output voltage divider) can drive another
  FLT input the same way if OVP has to be faster.
* The hardware trip has no blanking. If the turn-on current spike of the hard-switched
  bridge trips it, filter PC1 (RC) or set a digital filter for Fault 5 in CubeMX
  (filters 1 … 3 sample at f_HRTIM = 170 MHz with N = 2 … 8, i.e. ~12 … 47 ns delay).
* The minimum pulse is `PWR_TON_MIN_NS`; at no load the output may creep up.
* Both half-cycles always get the same on-time (atomic update); switch asymmetries
  still cause transformer DC bias — a series blocking capacitor is the usual cure.
